# Публикация Career Quest для жюри

Один Web Service Render обслуживает frontend и настоящий API по HTTPS.
Публичная ссылка появляется после развёртывания; наличие этих файлов в GitHub
ещё не означает, что сайт опубликован.

## Развернуть

1. Откройте [публикацию через Render](https://render.com/deploy?repo=https://github.com/BAITC-Hacks/hack-f746c068-ctrl-ai),
   зарегистрируйтесь через GitHub и разрешите доступ к репозиторию команды.
2. Создайте Blueprint из ветки `main` и корневого `render.yaml`.
   Конфигурация использует один Docker Web Service, план `0.5c-512mb` и диск 1 ГБ.
   Проверьте стоимость на экране Render и подтвердите создание сервиса.
3. Дождитесь статуса **Live**. При ошибке откройте **Logs** сервиса.
4. Откройте HTTPS-ссылку сервиса, указанную Render. На том же адресе
   `/api/health` должен вернуть `{"status":"ok"}`.
5. В странице сервиса откройте **Shell** и выполните:

   ```sh
   cat /var/data/access.json
   ```

6. Для первого входа скопируйте значение `token` из записи с `role: "employee"`
   и вставьте в форму входа сайта. Для HR используйте токен записи с `role: "hr"`.
   Передайте жюри ссылку и оба токена через закрытый канал сдачи проекта.
   Не добавляйте токены в README, исходный код или публичные сообщения.

Ориентир по цене: **$7/месяц за сервис + $0.25/месяц за диск 1 ГБ** на workspace
Hobby, без превышения включённых лимитов; итоговую сумму проверьте перед созданием.
[Тарифы Render](https://render.com/pricing).

## Проверить перед сдачей

1. Откройте публичную ссылку в приватном окне браузера и войдите сотрудником.
2. Для исходного E001 выполните EV002 (Architecture Mentoring): System Design
   изменится `2 → 3`, готовность — `81.73% → 86.54%`, первый следующий шаг — EV006.
   Если активность уже выполняли, исходные значения будут другими.
3. Обновите страницу: выполненная активность и прогресс должны сохраниться.
4. Выйдите и войдите токеном HR. Проверьте список сотрудников и HR-показатели.
5. Для импорта откройте `/api/docs`, нажмите **Authorize**, вставьте HR-токен
   и используйте маршруты импорта из [контракта API](API.md).
6. Добавьте проверенную публичную ссылку в материалы сдачи и README.

## Что настроено автоматически

`Dockerfile` собирает frontend с `VITE_USE_MOCK=false` и `VITE_API_URL=/api`.
Приложение `backend.web` раздаёт сайт в `/`, API — в `/api`; прямые переходы
и обновление страниц frontend работают по тому же адресу. Сервер слушает
`0.0.0.0` и порт из переменной `PORT`. Отдельно задавать адрес API и CORS не нужно.

`render.yaml` подключает постоянный диск `/var/data` и задаёт:

| Параметр | Значение |
| --- | --- |
| `CAREER_QUEST_STATE_PATH` | `/var/data/state.sqlite3` |
| `CAREER_QUEST_AUTH_FILE` | `/var/data/access.json` |
| Health check | `/api/health` |

Диск хранит прогресс и токены между перезапусками и обновлениями сервиса.
Сохраняются только файлы внутри его точки подключения.
[Постоянные диски Render](https://render.com/docs/disks).

Платный сервис не засыпает от отсутствия посетителей. Сохраняйте сервис активным
на время проверки жюри. При обновлении сервиса с диском возможен короткий перерыв.
Бесплатный Web Service засыпает после 15 минут без запросов и не поддерживает
постоянный диск; изменения SQLite и токены будут теряться при перезапусках.
[Ограничения бесплатного сервиса](https://render.com/docs/free).

## Запуск контейнера локально

Из корня репозитория при установленном Docker:

```sh
docker compose up --build -d
```

Откройте `http://localhost:8000`. Токены:

```sh
docker compose exec web cat /var/data/access.json
```

Swagger находится на `http://localhost:8000/api/docs`. Compose сохраняет
SQLite и токены в именованном Docker volume. Обычный `docker compose down`
останавливает приложение, сохраняя этот volume.
