# Career Quest — инструкции для разработки

## Источники требований

- Основное ТЗ — файл `HackAlem AI_ Career Quest - платформа геймификации жизненного цикла сотрудника..md` в корне репозитория, раздел «КЕЙС: CAREER QUEST». Voice Router в том же файле — отдельный кейс; не включай его в решение Career Quest без явного запроса.
- Когда появится стартовый кит, используй его схемы JSON/CSV и README для деталей данных и правил изменения навыков. Если README проекта расходится с ТЗ, уточняй реализацию по ТЗ и обновляй README по фактическому состоянию проекта.

## Обязательный результат

- Разрабатывай веб-приложение с двумя ролями: сотрудник и HR. Главный сценарий сотрудника: профиль и карьерная траектория → 1–3 рекомендуемых шага → выполнение активности → обновлённые навыки и прогресс.
- Профиль любого сотрудника должен показывать роль, грейд, навыки, историю активностей и доступные следующие шаги. Не привязывай логику к конкретным сотрудникам из стартового набора.
- Рекомендация должна учитывать как минимум три фактора из ТЗ: текущий грейд, разрывы по навыкам, историю участия и требования следующего грейда. Объяснение должно отражать факторы и значения, реально использованные при выборе. Правило «выбрать самый низкий навык» недостаточно.
- После отметки активности выполненной обновляй навыки по `gain` и `max_level` из `events.json`, затем пересчитывай траекторию и рекомендации. Показывай пользователю, как получился новый прогресс.
- HR-экран должен показывать распространённые дефициты навыков, сотрудников без рекомендованного шага и участие по активностям.
- Поддерживай загрузку дополнительных профилей и истории в формате стартового JSON/CSV: жюри проверяет решение на ранее неизвестных данных, включая пропуски и отказы.

## Ограничения и приоритеты

- Соблюдай разграничение доступа между сотрудником и HR. Данные о вовлечённости сотрудника не показывай другим сотрудникам без согласия. Используй только синтетические данные, не добавляй реальные персональные данные и секреты в репозиторий.
- Не вводи публичные рейтинги результативности и награды за обязательные процессы. Дополнительную геймификацию и другие опциональные функции делай после обязательного сценария.
- Ориентиры ТЗ: отклик интерфейса до 2 секунд, AI-рекомендация до 10 секунд. Качество и объяснимость рекомендаций важнее декоративных функций.
- Проект должен запускаться одной командой. По мере реализации поддерживай README в актуальном состоянии: зависимости, настройка, запуск, устройство решения и проверочный сценарий должны соответствовать работающему коду.

## Проверка изменений

- Для изменений в рекомендациях проверяй профили с конфликтующими факторами: низкий навык сам по себе не обязан определять следующий шаг, если история участия и требования грейда указывают на другое.
- Для изменений в данных и прогрессе проверяй импорт нового профиля и истории, отметку активности, применение `gain`/`max_level` и последующий пересчёт.
- Для изменений в интерфейсе и правах проверяй основной сценарий сотрудника, HR-экран и границы доступа. Указывай в результате, что проверено и какие ограничения остались.
